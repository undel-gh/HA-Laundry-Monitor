# Laundry Monitor 0.1.8-rc8

**Release candidate** — changes since [0.1.8-rc7](https://github.com/undel-gh/HA-Laundry-Monitor/releases/tag/0.1.8-rc7).

This update improves measurement reliability, restart recovery, Home Assistant
Recorder efficiency, and compatibility testing. Laundry Monitor remains a
passive washing-machine monitor: it does not control the appliance.

## Highlights

- **Fewer Recorder writes and a better duration source.**
  New `sensor.<device>_cycle_started_at` exposes the start of the active
  cycle. Frontends can calculate a live elapsed duration locally without
  publishing a new HA state every minute. Unchanged entity states no longer
  cause redundant publications; noisy debug entities are disabled by default
  on *new* installations.
  [#19](https://github.com/undel-gh/HA-Laundry-Monitor/pull/19)
- **Correct units for electricity readings.**
  Power and current are normalized to W and A using supported Home Assistant
  unit conversions (for example kW/mW and mA). Unsupported units or
  non-finite conversions are not treated as valid measurements.
  [#9](https://github.com/undel-gh/HA-Laundry-Monitor/pull/9)
- **Freshness from repeat reports.**
  Repeated valid power/current observations can refresh electrical evidence
  even when the value remains unchanged. Repeated vibration ON reports do
  *not* generate additional rising edges.
  [#10](https://github.com/undel-gh/HA-Laundry-Monitor/pull/10)
- **Safer recovery.**
  Invalid or timezone-naive stored cycle timestamps are rejected;
  recovery fails closed rather than reviving an active cycle without
  trustworthy timing.
  [#8](https://github.com/undel-gh/HA-Laundry-Monitor/pull/8)
- **More consistent diagnostics.**
  Downloadable Diagnostics, runtime and Repairs now agree on measurement
  validity, including incompatible units and conversion overflow.
  [#18](https://github.com/undel-gh/HA-Laundry-Monitor/pull/18)

## Compatibility and upgrade notes

**Home Assistant Core 2026.6.0+** remains the declared minimum.
The complete automated regression suite is configured for Core **2026.6.0**
(minimum) and **2026.10.4** (current fixture-supported test target), with
separate pinned fixture packages. This is not a claim of testing every
Home Assistant release or appliance setup.
[#22](https://github.com/undel-gh/HA-Laundry-Monitor/pull/22)

**Action for dashboards and automations using duration:**
`current_cycle_duration` is retained for compatibility but is no longer a
live ticking timer; it is a snapshot updated on meaningful state changes.
It is disabled by default on fresh installations, while prior registry
enable/disable choices remain intact. For a live counter, calculate
`now − cycle_started_at` in your **frontend** during `running` and
`final_spin`, and use `last_cycle_duration` once a cycle is finished.
Avoid using an HA template sensor with `now()` solely for a live display,
as it would reintroduce periodic Recorder writes.
[#19](https://github.com/undel-gh/HA-Laundry-Monitor/pull/19)

**Action for external Diagnostics parsers:**
`sources[*].available` now means the value is usable after unit-aware
validation, while `sources[*].entity_available` indicates whether the
Home Assistant entity has an available state. A power entity with a numeric
value but an unsupported unit can therefore be entity-available but
measurement-unavailable. This changes an existing diagnostics field's
meaning; update external parsers if applicable.
[#18](https://github.com/undel-gh/HA-Laundry-Monitor/pull/18)

The only mandatory input remains the power sensor; optional current input
can degrade without preventing power-only monitoring. Check Home Assistant
unit labels carefully: unsupported or incorrectly cased unit strings may
cause a reading to be treated as unavailable. Existing sensor/entity registry
preferences are preserved by these changes.
[#9](https://github.com/undel-gh/HA-Laundry-Monitor/pull/9)

The public `error` state indicates a **monitoring/input reliability issue**,
not a washing-machine error code. This documentation clarification does not
introduce a new machine-fault detector.
[#11](https://github.com/undel-gh/HA-Laundry-Monitor/pull/11)

## Validation and known limitations

This document is the **draft for the release-preparation PR**, not a claim
that `0.1.8-rc8` has already been published. Before publication, verify
the final `main` commit's green CI (both Core test suites, aggregate Tests,
Ruff, Hassfest and HACS); test a fresh HACS installation and upgrade from
`0.1.8-rc7`; review Home Assistant logs, entities and recovery; and record
the scope of any real-cycle field validation. The first live
`Audit published release / Release metadata` run must be checked after
publication. Neither HACS install/upgrade smoke testing nor a new physical
cycle test is claimed complete here.

A Home Assistant `state_reported` event proves that HA reported an entity
again, **not** necessarily that the underlying device sampled new data.
Live elapsed-time display requires frontend support for the new timestamp
sensor; the separately maintained Lovelace card is not updated by this
integration release.

To roll back, select the previous known-good published release in HACS
(if offered for your configured channel) and restore a Home Assistant backup
if needed. This RC must be marked **Pre-release** on GitHub
(`prerelease=true`); users may need to opt in to prerelease versions in
HACS. Historical RC release metadata is not modified by this release.
