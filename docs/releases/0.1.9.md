# Laundry Monitor 0.1.9

[Русский текст](https://github.com/undel-gh/HA-Laundry-Monitor/blob/0.1.9/docs/releases/0.1.9.ru.md)

**Stable maintenance release — safer restart recovery, stricter persisted
data validation, and a simpler documentation structure.**

This release covers the five PRs merged after the published
[0.1.8 stable](https://github.com/undel-gh/HA-Laundry-Monitor/releases/tag/0.1.8) release.
It does not introduce a new detection algorithm or require recalibration.

## Changes

### Safer recovery after a Home Assistant restart

- A partially corrupted saved snapshot no longer necessarily discards all
  history. Valid independent laundry-tracking data (laundry presence and
  last unload timestamp) and completed-cycle duration/energy statistics
  are preserved where safe. Invalid optional fields degrade individually.
- Missing, malformed or timezone-naive `last_state_change` forces a safe
  recovery to `idle`, regardless of the previously saved cycle state.
  The integration records `state_recovery_fallback`, clears active-cycle
  context and schedules a sanitized snapshot save. Invalid active-cycle
  start timing still prevents resuming an untrustworthy active cycle.
- Invalid mandatory non-timing identity/state fields still reject the
  whole snapshot. Recovery does not fabricate start, final-spin,
  completion, unload or state-change events. Existing valid snapshots
  retain their behavior.
  [#15](https://github.com/undel-gh/HA-Laundry-Monitor/issues/15) · [#29](https://github.com/undel-gh/HA-Laundry-Monitor/pull/29)

### Stricter validation of saved statistics and heating context

- Optional duration/energy statistics reject boolean, non-finite,
  non-numeric and overflowing values without losing unrelated valid data.
  Valid finite numeric strings and real zero remain supported.
- Persisted energy units must be non-empty strings (trimmed); invalid
  units are discarded rather than converted into fictitious labels.
  A valid amount with unknown unit can still be recovered; the integration
  does not calculate a new completed-cycle energy delta without matching
  known units. Invalid amounts cannot retain orphaned units.
- A malformed numeric heating threshold in the saved fingerprint cannot
  authorize restored `not_seen` heating evidence. Independent valid
  latched `detected` evidence and history remain recoverable.
  [#30](https://github.com/undel-gh/HA-Laundry-Monitor/issues/30) · [#32](https://github.com/undel-gh/HA-Laundry-Monitor/pull/32)

### Internal maintainability and regression coverage

- The ordered, heating-aware spin-confirmation policy is now isolated
  in a pure decision function. Gate precedence, thresholds, diagnostics,
  detector evaluation, state transitions and event payloads are intended
  to remain unchanged; the runtime still owns all Home Assistant effects.
  The existing heated-hybrid 45-second electrical maturity and
  correlated vibration-edge requirements are preserved.
- New pure-policy boundary tests and runtime regression tests cover
  confirmation/rejection, diagnostic reasons and event contracts.
  This is a behavior-preserving refactor, not a new spin-detection feature.
  [#3](https://github.com/undel-gh/HA-Laundry-Monitor/issues/3) · [#31](https://github.com/undel-gh/HA-Laundry-Monitor/pull/31)

### Documentation and CI

- A bilingual [documentation index](https://github.com/undel-gh/HA-Laundry-Monitor/blob/0.1.9/docs/README.md)
  now separates user guides, canonical technical references, maintainer
  procedures and versioned release notes. Historical published notes
  remain unchanged. Former language-directory paths and the redundant
  card-link page have been removed from the current tree; old links to
  those files on `main` no longer resolve. Tagged historical copies remain.
- Read-only Markdown link/heading-anchor validation and its nine unit
  tests are now part of the required CI gate. The checker validates
  repository-local links; external URLs are intentionally not checked.
  [#28](https://github.com/undel-gh/HA-Laundry-Monitor/issues/28) · [#33](https://github.com/undel-gh/HA-Laundry-Monitor/pull/33) · [#35](https://github.com/undel-gh/HA-Laundry-Monitor/pull/35)

## Compatibility and upgrade notes

- Minimum Home Assistant Core remains **2026.6.0**. Full automated suites
  target **2026.6.0**, **2026.10.4** and **2026.11.1**; these are CI
  targets, not physical field-test coverage for every HA version.
- Storage schema version stays **1**. No configuration migration,
  entity/event rename, new required sensor or changed detector threshold
  is introduced. Existing valid snapshots and legacy finite numeric
  strings remain compatible. Corrupt data is handled more conservatively
  as described above.
- Existing dashboards, Diagnostics contracts and Recorder behavior
  are unchanged from 0.1.8. The separate
  [Laundry Monitor Card](https://github.com/undel-gh/Laundry-Monitor-Card)
  is not installed or upgraded by this release.
- Update bookmarks to the new documentation paths. This project is
  distributed through HACS as a custom repository; this release is
  not an announcement of HACS Default inclusion.
- Intended publication: tag `0.1.9`, regular GitHub Release
  (`prerelease=false`), on the verified post-merge main commit.
  Published 0.1.8 and older tags/releases are not modified.

## Known limitations and rollback

- Corruption of mandatory non-timing fields can still make a snapshot
  unusable. Partial recovery is not a guarantee of reconstructing a
  lost or invalid active cycle.
- Hybrid final-spin confirmation remains optional and experimental.
  Calibrate for the individual machine; conservative inactivity-based
  completion remains available when terminal spin is not confirmed.
  The integration monitors sensors and does not diagnose or control the
  washing machine.
- [#34 — canonical documentation review before 1.0.0](https://github.com/undel-gh/HA-Laundry-Monitor/issues/34)
  remains planned, including requirements traceability and documentation
  cleanup. It is not an identified blocking regression for 0.1.9.
- Back up Home Assistant before upgrading. If necessary, select the
  previously published 0.1.8 in HACS and restore a known-good backup.
  Older code may not salvage the same damaged snapshot. Do not rewrite
  published tags or release assets.
