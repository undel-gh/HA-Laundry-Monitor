# Laundry Monitor 0.1.8-rc8

**Предварительный релиз (RC)** — изменения после
[0.1.8-rc7](https://github.com/undel-gh/HA-Laundry-Monitor/releases/tag/0.1.8-rc7).

Обновление повышает надёжность обработки измерений, восстановления
после перезапуска и совместимость с Home Assistant, а также сокращает
ненужные записи в Recorder. Интеграция по-прежнему только наблюдает
за стиральной машиной и не управляет ею.

## Основные изменения

- **Меньше записей в Recorder и новый источник длительности.**
  Добавлен `sensor.<device>_cycle_started_at` — время начала
  активного цикла. Длительность можно вычислять на стороне интерфейса,
  не записывая состояние в HA каждую минуту. Неизменившиеся состояния
  повторно не публикуются; шумные диагностические сущности по
  умолчанию отключены на **новых** установках.
  [#19](https://github.com/undel-gh/HA-Laundry-Monitor/pull/19)
- **Нормализация электрических измерений.**
  Мощность и ток преобразуются в Вт и А с поддержкой единиц HA,
  включая kW, mW и mA. Неподдерживаемые единицы и результаты преобразования,
  не являющиеся конечными числами, считаются недостоверными.
  [#9](https://github.com/undel-gh/HA-Laundry-Monitor/pull/9)
- **Повторные показания обновляют свежесть.**
  Новый отчёт мощности/тока учитывается даже при неизменившемся
  числовом значении. При этом повторные сообщения о вибрации
  не создают искусственных фронтов.
  [#10](https://github.com/undel-gh/HA-Laundry-Monitor/pull/10)
- **Более безопасное восстановление.**
  Некорректные и не содержащие часовой пояс временные метки
  не допускают восстановления активного цикла с недостоверным
  временем.
  [#8](https://github.com/undel-gh/HA-Laundry-Monitor/pull/8)
- **Согласованная диагностика.**
  Downloadable Diagnostics, runtime и Repairs используют одинаковые
  правила проверки электрических измерений и их единиц.
  [#18](https://github.com/undel-gh/HA-Laundry-Monitor/pull/18)

## Совместимость и действия после обновления

Минимальная версия Home Assistant Core — **2026.6.0**. Полный CI-набор
предусмотрен для Core **2026.6.0** и **2026.10.4** (последняя
выбранная пара Core/fixture для тестов, не обязательно новейший релиз HA).
Это не подтверждает испытания всех версий HA и моделей стиральных машин.
[#22](https://github.com/undel-gh/HA-Laundry-Monitor/pull/22)

**Если вы используете `current_cycle_duration`:** эта сущность
сохранена для совместимости, но больше не работает как непрерывный
таймер. Она показывает снимок длительности при значимых изменениях
состояния. На новых установках по умолчанию отключена; прежние
настройки Entity Registry сохраняются. Для живого счётчика вычисляйте
`текущее время − cycle_started_at` прямо в интерфейсе, пока состояние
`running` или `final_spin`; после `finished` используйте
`last_cycle_duration`. **Избегайте** Template Sensor с `now()`
только ради отображения живого счётчика: он создаёт новые
периодические записи в Recorder.
[#19](https://github.com/undel-gh/HA-Laundry-Monitor/pull/19)

**Если вы разбираете экспорт Diagnostics:** значение
`sources[*].available` теперь означает **пригодность измерения**,
а новое `sources[*].entity_available` — доступность состояния
сущности в HA. Например, датчик мощности с числом в неподдерживаемых
вольтах может иметь `entity_available=true`, но `available=false`.
При необходимости обновите внешние парсеры.
[#18](https://github.com/undel-gh/HA-Laundry-Monitor/pull/18)

Обязательным остаётся только датчик мощности. Некорректный
необязательный датчик тока не блокирует мониторинг по мощности.
Единицы измерения HA учитываются в точном регистре; ошибочные
обозначения могут сделать показание недоступным.
[#9](https://github.com/undel-gh/HA-Laundry-Monitor/pull/9)

Состояние `error` означает **проблему достоверности мониторинга**,
а не код неисправности самой стиральной машины. Это уточнение
документации, а не новый детектор поломок.
[#11](https://github.com/undel-gh/HA-Laundry-Monitor/pull/11)

## Проверки, ограничения и откат

**Это черновик для release-PR, а не объявление об опубликованном RC.**
До публикации необходимо убедиться в успешном CI на итоговом коммите
`main` (оба набора Core, агрегирующий Tests, Ruff, Hassfest и HACS),
проверить чистую установку и обновление через HACS с `0.1.8-rc7`,
логи и восстановление после перезапуска. Результаты полевой проверки
реального цикла следует зафиксировать отдельно. Ни установка/обновление
через HACS, ни новый полевой цикл пока **не объявляются проверенными**.
После публикации нужно проверить первый успешный запуск workflow
`Audit published release / Release metadata`.

Повторный отчёт `state_reported` свидетельствует о публикации
в Home Assistant, но не доказывает новое физическое измерение датчика.
Для непрерывного отображения длительности требуется поддержка
`cycle_started_at` в интерфейсе; отдельная Lovelace-карточка в данный
релиз интеграции не входит.

Для отката выберите ранее опубликованную исправную версию в HACS
(если она доступна в выбранном канале) и при необходимости
восстановите резервную копию Home Assistant.

**Важное изменение канала обновлений HACS:** предыдущие RC
(`0.1.8-rc3`–`0.1.8-rc7`) ошибочно опубликованы с
`prerelease=false`, поэтому HACS мог предлагать их без подписки на
предварительные версии. `0.1.8-rc8` впервые будет опубликован
корректно — с отметкой **Pre-release** (`prerelease=true`) и без
назначения Latest. **Без включённого переключателя Pre-release для
этого репозитория HACS не предложит rc8 как обычное обновление.**
Для получения RC необходимо явно включить предварительные версии
репозитория. При проверке чистой установки и обновления с rc7
необходимо проверить поведение HACS как с выключенным, так и со
включённым переключателем. Метаданные старых RC этим выпуском
не изменяются.
