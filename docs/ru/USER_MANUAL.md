# Laundry Monitor — Руководство пользователя

> **Статус документа:** первая версия руководства пользователя для текущей реализации Laundry Monitor.
>
> Канонической технической документацией проекта является английская версия. Русское руководство поддерживается как пользовательский перевод.

## 1. Для чего нужен Laundry Monitor

Laundry Monitor — пользовательская интеграция Home Assistant создаёт в Home Assistant логическое устройство мониторинга стиральной машины на основе существующих сущностей датчиков.

Интеграция **не подключается к стиральной машине напрямую и не управляет ею**. Вместо этого она наблюдает электрические и, при наличии, физические сигналы и определяет текущее состояние цикла.

Интеграция может определять, что стиральная машина:

- простаивает;
- подготовлена и ожидает запуска цикла;
- выполняет программу;
- вошла в вероятную заключительную последовательность отжима / терминальную фазу;
- завершила цикл;
- не может надёжно оцениваться из-за недоступности обязательного источника.

Дополнительно Laundry Monitor может:

- использовать измерение тока как дополнительный признак активности;
- использовать датчик двери для контекста перед запуском и регистрации открытия после завершения;
- использовать датчик вибрации для определения терминальной фазы;
- объединять вибрацию и устойчивый электрический профиль в опциональном гибридном детекторе отжима;
- независимо контролировать датчик протечки;
- рассчитывать энергопотребление цикла при наличии датчика энергии;
- отслеживать, считается ли бельё всё ещё находящимся в машине.

Laundry Monitor работает пассивно. Интеграция не переключает умную розетку, не отправляет уведомления, не включает сирены, не запускает и не останавливает стиральную машину и не изменяет внешние сущности.

## 2. Требования

### 2.1 Home Assistant

Требуется Home Assistant **2026.6.0 или новее**.

### 2.2 Обязательный источник

Необходим датчик мощности Home Assistant:

- домен: `sensor`;
- device class: `power`;
- значение: активная мощность, обычно в ваттах.

Пример:

```text
sensor.washing_machine_power
```

Датчик мощности является основным и авторитетным источником для подтверждения запуска цикла.

### 2.3 Опциональные источники

Laundry Monitor также может использовать:

| Источник | Тип Home Assistant | Назначение |
| --- | --- | --- |
| Датчик тока | `sensor`, device class `current` | Дополнительный признак значимой активности и диагностика hybrid |
| Датчик двери | `binary_sensor`, `door` или `opening` | Подготовка к запуску и события открытия после завершения |
| Датчик вибрации | `binary_sensor`, `vibration` | Признаки терминального отжима |
| Датчик протечки | `binary_sensor`, `moisture` | Независимый контроль протечки |
| Датчик энергии | `sensor`, device class `energy` | Статистика энергопотребления последнего цикла |
| Выключатель умной розетки | `switch` | Только диагностика |

Для базового мониторинга обязателен только датчик мощности.

Опциональные источники могут становиться недоступными. Потеря такого источника должна отключать соответствующую дополнительную функцию, но не останавливать базовый мониторинг по мощности.

## 3. Установка

### 3.1 Через пользовательский репозиторий HACS

1. Откройте **HACS**.
2. Откройте **Custom repositories**.
3. Добавьте:

   ```text
   https://github.com/undel-gh/HA-Laundry-Monitor
   ```

4. Выберите категорию **Integration**.
5. Найдите **Laundry Monitor** в HACS и установите интеграцию.
6. Перезапустите Home Assistant.

### 3.2 Ручная установка

1. Скопируйте:

   ```text
   custom_components/laundry_monitor
   ```

   в:

   ```text
   <config>/custom_components/
   ```

2. Перезапустите Home Assistant.

---

## 4. Добавление стиральной машины

Настройка выполняется через интерфейс Home Assistant. YAML не требуется.

1. Откройте **Настройки → Устройства и службы**.
2. Нажмите **Добавить интеграцию**.
3. Найдите **Laundry Monitor**.
4. Укажите понятное имя стиральной машины.
5. Выберите обязательный датчик мощности.
6. Выберите доступные опциональные источники.
7. Включите **Laundry Tracking**, если нужно отслеживать наличие белья до явного подтверждения выгрузки.

Для каждой стиральной машины создавайте отдельную запись Laundry Monitor.

Один и тот же датчик мощности нельзя использовать одновременно в нескольких записях Laundry Monitor.

## 6. Состояния цикла

Laundry Monitor создаёт пользовательский сенсор состояния цикла.

| Состояние | Значение |
| --- | --- |
| `idle` | Активный цикл не отслеживается. |
| `armed` | Контекст двери указывает, что цикл может скоро начаться. |
| `running` | Цикл стирки подтверждён и выполняется. |
| `final_spin` | Обнаружена вероятная заключительная последовательность отжима / терминальная фаза. |
| `finished` | Завершение цикла подтверждено. |
| `error` | Надёжная оценка невозможна, например при длительной потере обязательного датчика мощности. |

### 6.1 Что означает `final_spin`

Историческое имя состояния — `final_spin`, однако его следует понимать как **«обнаружена терминальная фаза»**, а не как «барабан непрерывно вращается на максимальных оборотах».

Терминальная фаза может включать:

- несколько этапов отжима;
- изменение оборотов барабана;
- короткие остановки;
- работу насоса и слив;
- позиционирование барабана;
- электрическую активность после остановки вращения;
- сигналы окончания программы.

После подтверждения терминальной фазы обычная заключительная активность не переводит интеграцию автоматически обратно в `running`.

---

## 7. Как определяется запуск цикла

Основным источником запуска является мощность.

Кандидат на запуск появляется, когда мощность достигает настроенного **порога запуска**. Условие должно сохраняться в течение **времени подтверждения запуска**, после чего цикл переводится в `running`.

Подтверждение позволяет отфильтровать короткие всплески мощности.

Опциональный датчик тока может участвовать в определении значимой активности, но ток сам по себе не может запустить цикл.

### Важное правило проверки настроек

**Порог активности по мощности** не должен быть выше **порога запуска**.

---

## 8. Значимая активность

Laundry Monitor использует значимую электрическую активность для отличия работы машины от периодов тишины.

Мощность на уровне или выше **порога активности по мощности** считается активностью по мощности.

Если датчик тока настроен и доступен, ток на уровне или выше **порога активности по току** также считается значимой активностью.

Используется логика OR:

```text
активность по мощности
ИЛИ
активность по току
=
значимая активность
```

При этом ток остаётся дополнительным источником:

- один ток не подтверждает запуск цикла;
- один ток не подтверждает final spin;
- один ток не подтверждает завершение цикла.

## 9. Нулевые значения и недоступность источника

Корректное числовое значение ноль является реальными данными.

```text
0 W ≠ unavailable
0 A ≠ unavailable
```

Примеры:

- Доступная умная розетка, выключенная кнопкой и сообщающая `0 W`, передаёт корректную информацию: питание на стиральную машину не подаётся.
- Во время реальной паузы машина также может корректно сообщать `0 W`.
- `unavailable`, `unknown`, некорректное или отсутствующее значение мощности означает, что у Laundry Monitor нет достоверного измерения.

Laundry Monitor не должен считать корректные `0 W` или `0 A` потерей источника.

И наоборот, недоступные или отсутствующие данные не должны искусственно превращаться в ноль.

Это различие особенно важно при маломощных паузах и сбоях связи.

## 10. Определение заключительного отжима

Laundry Monitor может подтвердить терминальную фазу двумя способами.

### 10.1 Только по вибрации

Если настроен датчик вибрации, Laundry Monitor подсчитывает переходы вибрации OFF → ON в скользящем временном окне.

Обычное подтверждение по вибрации требует:

- настроенного числа событий вибрации;
- попадания всех нужных событий в окно вибрации;
- достижения минимального возраста цикла;
- достаточно свежей значимой электрической активности.

При стандартных настройках:

```text
3 события вибрации
за 180 секунд
после минимум 600 секунд цикла
при наличии недавней электрической активности
```

### 10.2 Гибридный путь: вибрация + электрический профиль

Гибридное подтверждение является опциональным и по умолчанию выключено.

Оно предназначено, в частности, для датчиков вибрации, которые могут пропускать физические события или долго оставаться в состоянии ON, из-за чего возникает слишком мало фронтов OFF → ON.

Для hybrid требуются:

- включённый hybrid;
- настроенный датчик вибрации;
- настроенный порог мощности электрического отжима;
- уменьшенное, но всё ещё значимое количество событий вибрации;
- устойчивый электрический кандидат отжима;
- достижение минимального возраста цикла;
- недавняя значимая активность;
- свежие данные электрического источника.

**Одного электрического сигнала недостаточно для подтверждения final spin.**

### 10.3 Электрический кандидат отжима

Электрический детектор использует взвешенную по времени скользящую медиану, а не одиночное мгновенное измерение.

Основные параметры:

- **Окно электрического отжима** — скользящее окно наблюдений;
- **Минимальное покрытие** — минимальное время реальных данных внутри окна;
- **Максимальный возраст электрического источника** — максимально допустимое время экстраполяции последнего реального измерения;
- **Порог мощности электрического отжима** — индивидуальный порог мощности;
- **Порог тока электрического отжима** — опциональный подтверждающий порог тока.

Ограничение freshness не позволяет старому высокому значению мощности бесконечно поддерживать hybrid-кандидат, если сенсор перестал обновляться, хотя формально остаётся available.

### 10.4 Подтверждение по току

Ток используется только как дополнительное подтверждение.

Решение hybrid опирается на мощность. Порог тока позволяет диагностике показать, что профиль тока согласуется с выводом, однако непревышение порога тока само по себе не блокирует hybrid.

### 10.5 Как выбирать пороги hybrid

Не копируйте пороги мощности и тока с другой стиральной машины без проверки её реального электрического профиля.

Практический порядок калибровки:

1. Оставьте hybrid выключенным.
2. Соберите историю нескольких полных циклов.
3. Сопоставьте события вибрации с историей мощности/тока во время физического заключительного отжима.
4. Выберите порог мощности, который устойчиво наблюдается во время нужной сигнатуры, но не является обычным для несвязанной поздней активности.
5. Настройте порог тока как дополнительный диагностический признак.
6. Включите отключённые по умолчанию диагностические сущности electrical/hybrid.
7. Проверьте несколько циклов в shadow mode.
8. Включайте реальное гибридное подтверждение только после отсутствия ложных terminal-spin candidates.

Значения вроде `100 W` и `0.7 A` могут подходить конкретной измеренной машине, но **не являются универсальными рекомендациями**.

### 10.6 Ограничения конфигурации hybrid

Laundry Monitor не позволяет сохранить противоречивые настройки hybrid.

В частности:

- hybrid требует датчика вибрации;
- hybrid требует заданного порога мощности электрического отжима;
- количество событий вибрации hybrid должно быть меньше обычного количества для vibration-only;
- минимальное electrical coverage не может быть больше electrical window;
- при включённом hybrid нельзя через reconfigure удалить датчик вибрации.

## 11. Определение завершения цикла

Laundry Monitor использует период отсутствия значимой активности, а не пытается распознать точное значение standby-мощности.

### 11.1 После `final_spin`

После обнаружения терминальной фазы любая значимая активность перезапускает таймер завершения.

Если значимая активность отсутствует в течение **подтверждения завершения после final spin**, состояние становится `finished`.

По умолчанию:

```text
180 секунд
```

### 11.2 Резервный путь без final spin

Если терминальная фаза не была обнаружена, в состоянии `running` используется более длинный консервативный таймер отсутствия активности.

По умолчанию:

```text
600 секунд
```

Благодаря этому цикл может завершиться даже без датчика вибрации или при недостаточном количестве признаков final spin.

---

## 12. Поведение датчика двери

Датчик двери опционален.

При его наличии он может давать контекст до и после цикла.

Типовое поведение:

- закрытие двери может перевести интеграцию в `armed`;
- открытие двери до запуска может вернуть состояние в `idle`;
- открытие двери после `finished` может создать диагностическое событие.

Открытие двери после завершения **не означает автоматически, что бельё вынуто**.

---

## 13. Laundry Tracking

Laundry Tracking — опциональная функция.

При включении появляются:

- `binary_sensor.<device>_laundry_present`;
- `button.<device>_mark_unloaded`;
- `sensor.<device>_last_unloaded_at`.

После запуска цикла бельё считается находящимся в машине и остаётся таким после завершения.

Чтобы сообщить Laundry Monitor, что бельё действительно вынуто, нажмите **Mark unloaded / Отметить выгруженным**.

Само открытие двери наличие белья не сбрасывает.

Если Laundry Tracking выключен, состояние `finished` сохраняется заданное время, после чего автоматически возвращается в `idle`.

---

## 14. Контроль протечки

Если настроен датчик протечки, Laundry Monitor контролирует его независимо от состояния стирки.

Обнаружение протечки не изменяет состояние цикла.

Это сделано намеренно: протечка относится к безопасности, а `idle`, `running`, `final_spin` и `finished` описывают жизненный цикл стирки.

Для уведомления, сирены или отключения другого устройства используйте обычные автоматизации Home Assistant.

---

## 15. Основные сущности

Entity ID зависит от настроенного имени стиральной машины.

Основные пользовательские сущности:

| Сущность | Назначение |
| --- | --- |
| `sensor.<device>_cycle_state` | Текущее публичное состояние цикла |
| `binary_sensor.<device>_running` | Включён в состояниях `running` и `final_spin` |
| `binary_sensor.<device>_finished` | Включён при `finished` |
| `binary_sensor.<device>_final_spin_detected` | Защёлкивается после подтверждения terminal spin |
| `sensor.<device>_current_cycle_duration` | Длительность текущего цикла |
| `sensor.<device>_last_cycle_duration` | Длительность последнего завершённого цикла |
| `sensor.<device>_last_cycle_energy` | Энергия последнего цикла, если настроен датчик энергии |

Дополнительные диагностические сущности показывают внутреннее состояние детекторов.

Некоторые экспериментальные electrical/hybrid diagnostics по умолчанию отключены в реестре сущностей. При настройке или диагностике hybrid включите их на странице устройства/сущностей.

Полезные hybrid diagnostics:

- путь подтверждения final spin;
- количество и confidence событий вибрации;
- electrical spin candidate;
- скользящая медиана мощности;
- опциональная скользящая медиана тока;
- время начала electrical candidate;
- отметки времени активности.

Путь подтверждения показывает, каким способом был получен `final_spin`:

```text
vibration_only
```

или:

```text
hybrid
```

Диагностический confirmation path не является авторитетным сохраняемым состоянием цикла и после перезапуска может быть очищен.

## 16. События и автоматизации

Laundry Monitor создаёт события Home Assistant для основных наблюдений жизненного цикла.

Основные события:

- `laundry_monitor.cycle_started`;
- `laundry_monitor.final_spin_detected`;
- `laundry_monitor.cycle_finished`;
- `laundry_monitor.door_opened_after_finish`;
- `laundry_monitor.machine_unloaded`;
- `laundry_monitor.leak_detected`;
- `laundry_monitor.state_changed`;
- `laundry_monitor.transition_rejected`.

Сама интеграция уведомления не отправляет.

Пример автоматизации уведомления:

```yaml
automation:
  - alias: "Стирка завершена"
    trigger:
      - platform: event
        event_type: laundry_monitor.cycle_finished
    action:
      - service: notify.mobile_app_phone
        data:
          message: "Стиральная машина завершила программу."
```

Также в автоматизациях можно использовать обычные binary sensors или сенсор состояния цикла.

---

## 17. Изменение датчиков и параметров

В интерфейсе используются два разных действия.

### Reconfigure / Перенастроить

Используйте **Reconfigure**, чтобы менять источники и Laundry Tracking.

Например:

- заменить датчик мощности;
- добавить или убрать датчик тока;
- добавить датчик вибрации;
- заменить датчик двери;
- добавить датчик энергии или протечки.

При reconfigure проверяются обязательные ограничения hybrid.

### Configure / Параметры

Используйте **Configure**, чтобы менять пороги детекторов и таймеры жизненного цикла.

При калибровке реальной машины не меняйте сразу множество параметров. Меняйте одну логическую группу, собирайте полный цикл и сравнивайте результат.

---

## 18. Перезапуск и восстановление

Laundry Monitor сохраняет runtime-информацию, чтобы перезапуск Home Assistant не обязательно сбрасывал активный цикл.

Сохранённый snapshot активного цикла восстанавливается только при допустимом возрасте согласно параметру **Maximum snapshot age**.

Восстановление выполняется консервативно: устаревшее или небезопасное runtime-состояние не должно восстанавливаться вслепую.

Временные rolling electrical evidence и диагностический confirmation path после рестарта могут быть перестроены или очищены.

---

## 19. Потеря обязательного датчика мощности

Датчик мощности обязателен.

Кратковременное состояние `unavailable`, `unknown`, отсутствие или нечисловое значение допускается в течение **Power sensor unavailable grace period**.

Если обязательный источник остаётся непригодным дольше этого времени, Laundry Monitor может перейти в `error` и создать issue в Home Assistant Repairs.

Помните:

```text
корректные 0 W
```

не являются потерей источника.

Недоступностью считается именно отсутствие достоверного числового наблюдения.

---

## 20. Устранение неполадок

### Цикл не запускается

Проверьте:

- доступен ли датчик мощности и является ли его значение числовым;
- превышает ли машина **порог запуска**;
- сохраняется ли стартовая мощность в течение всего **времени подтверждения запуска**;
- не установлен ли порог активности выше порога запуска.

### Цикл запускается от коротких всплесков

Увеличьте **Start confirmation** и проверьте, не слишком ли низок **Start threshold**.

### `final_spin` никогда не определяется

Для vibration-only:

- проверьте, создаёт ли датчик вибрации переходы OFF → ON;
- посмотрите интервалы между событиями;
- проверьте окно вибрации;
- проверьте минимальное время цикла;
- убедитесь, что электрическая активность достаточно свежая.

Если датчик физически видит отжим, но создаёт слишком мало rising edges, после индивидуальной калибровки может помочь hybrid.

### Hybrid слишком рано подтверждает `final_spin`

Сначала выключите hybrid, затем изучите:

- время событий вибрации;
- rolling median мощности;
- electrical threshold;
- минимальный возраст цикла;
- electrical coverage;
- freshness источника;
- возникает ли аналогичный электрический профиль при нагреве или обычной стирке.

Не повышайте и не меняйте порог без анализа полных циклов.

### Hybrid не подтверждает final spin

Проверьте:

- включён ли hybrid;
- настроен ли датчик вибрации;
- задан ли electrical power threshold;
- достаточно ли событий вибрации;
- достигает ли rolling median порога мощности;
- достигнуто ли минимальное coverage;
- прошёл ли минимальный возраст цикла;
- остаётся ли источник мощности свежим;
- есть ли недавняя значимая активность.

### `finished` появляется поздно

Посмотрите время последней значимой активности. Любая подходящая активность по мощности или току перезапускает таймер завершения.

Если `final_spin` не определён, используется более длинный fallback timer из `running`.

### Датчик тока стал unavailable

Базовый мониторинг должен продолжиться только по мощности.

Недоступный current нельзя интерпретировать как `0 A`.

### Датчик мощности показывает `0 W`

Если сущность доступна и значение числовое, `0 W` — корректные данные. Это нормально для выключенного выхода умной розетки, остановленной машины или настоящего нулевого интервала.

### Интеграция перешла в `error`

Проверьте обязательный датчик мощности и Home Assistant Repairs.

Длительный `unavailable`/`unknown`/нечисловой источник мощности принципиально отличается от корректного числового нуля.

## 21. Debug logging и diagnostics

При неожиданном поведении:

1. Откройте интеграцию или устройство Laundry Monitor в Home Assistant.
2. Включите **debug logging**.
3. Воспроизведите нужную часть цикла, по возможности полный цикл.
4. Остановите debug logging.
5. Скачайте diagnostics.

Diagnostics могут содержать:

- настроенные источники и их availability;
- текущее runtime-состояние;
- пороги детекторов;
- vibration evidence;
- electrical/hybrid statistics;
- отметки времени активности;
- таймеры finish;
- статистику цикла;
- сохранённый snapshot;
- отклонённые переходы.

При проблемах с hybrid по возможности заранее включите отключённые диагностические сущности hybrid/electrical, чтобы их история попала в наблюдения.

---

## 22. Обновление Laundry Monitor

При обновлении через HACS:

1. Установите новую версию.
2. Перезапустите Home Assistant, если это требуется.
3. Откройте запись Laundry Monitor.
4. Проверьте options, если в release notes появились новые параметры детекторов.
5. Убедитесь, что обязательные и опциональные источники сохранились.
6. После изменений алгоритмов наблюдайте хотя бы один полный цикл, прежде чем считать прежнюю калибровку оптимальной.

Не переносите параметры настройки с другой стиральной машины без проверки её профиля.

---

## 23. Несколько стиральных машин

Для каждой машины создайте отдельную config entry Laundry Monitor.

У каждой записи собственные:

- обязательный датчик мощности;
- набор опциональных источников;
- пороги;
- состояние цикла;
- статистика;
- состояние Laundry Tracking.

Не используйте один датчик мощности одновременно в нескольких записях.

---

## 24. Рекомендуемый checklist перед постоянным использованием

Перед тем как использовать новую настройку машины в ежедневных автоматизациях, проследите несколько полных циклов и убедитесь, что:

- запуск определяется стабильно;
- обычные маломощные паузы не завершают цикл;
- `final_spin` не появляется во время несвязанной ранней или средней активности;
- после реального окончания цикл переходит в `finished`;
- потеря датчика мощности отличается от корректных `0 W`;
- Laundry Tracking работает ожидаемо, если включён;
- hybrid не создаёт ложных переходов в терминальную фазу, если он включён;
- по возможности проверены разные программы и нетипичные режимы.

Настройки детекторов описывают электрическое и вибрационное поведение конкретной установки. Рассматривайте их как калибровку, а не как универсальный профиль стиральной машины.
